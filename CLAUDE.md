# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code **plugin** (`nk-work-kit`) and its own **marketplace** (`nayot-buu`), both in this repo, for day-to-day work in the Faculty of Engineering, Burapha University (BUU). There is no build, lint or test suite. Each skill is a `skills/<name>/SKILL.md` prompt that drives one standalone script in `scripts/`.

## Running scripts directly

```bash
python3 scripts/build_memo.py examples/grade_correction_nai.json   # → /tmp/memo_grade_correction.odt
libreoffice --headless --convert-to pdf /tmp/memo_grade_correction.odt
# macOS: /Applications/LibreOffice.app/Contents/MacOS/soffice

python3 scripts/docnum.py login | whoami | list [--json] [--all] | request ... | cancel <docNumber>
uv run scripts/check_pending.py [--json] [--only edoc|esign]
uv run scripts/edoc_digest.py [--receive] [--all] [--limit N] [--inbox NAME] [--json]
uv run scripts/eleave.py balance | status [--year Y] | types | fields <type> | request spec.json [--confirm ID] | cancel --start DATE [--confirm]
uv run scripts/transcribe.py rec.m4a --model google/gemini-2.5-flash --yes
uv run scripts/gcontacts.py search <q> | create contact.json [--force] | update people/c… --add-email … --note …
python3 scripts/make_vcf.py contact.json out.vcf
uv run scripts/triage_send.py --show-config | --subject S --html F [--mark-run ISO] [--dry-run]
scripts/triage_run [--dry-run]
python3 scripts/edu_claim.py check|fill SPEC.json [OUT.pdf] | pack PACK.json | blank OUT.pdf [--form gov] | words N | where
python3 scripts/pay_sheet.py build|check DIR | mark DIR ROW --ref R --date D --slip IMG | payload NUMBER AMOUNT
uv run scripts/pf_test.py                                          # offline tests: personal-finance Txn IDs (overlapping statements, twins)
python3 scripts/meet_attendees_test.py                             # offline tests: Meet name ↔ invite matching
uv run scripts/projects_test.py                                    # offline tests: project Kanban board
uv run scripts/projects.py list [--json] | dashboard | kanban | digest [--days N] | notify [--dry-run] [--force] | waiting [--days N] [--json] | scan-inbox [--dry-run] | new "Name"

uv run --with playwright==1.60.0 playwright install chromium        # one-time, for check_pending
```

Local plugin install for testing: `claude plugin marketplace add ./` then `claude plugin install nk-work-kit@nayot-buu`.

## Architecture and conventions

- **Skills reference scripts via `${CLAUDE_PLUGIN_ROOT}/scripts/...`**, with a fallback note for when it is unset. Never hardcode the plugin name or install path: the plugin installs into a version-pinned cache dir (`~/.claude/plugins/cache/nayot-buu/nk-work-kit/<version>/`), and the v2.0.0 rename broke a hardcoded path.
- **One config file for all skills:** `~/.config/nk-work-kit/.env` (template: `scripts/.env.example`). Lookup order: real env vars → `$XDG_CONFIG_HOME/nk-work-kit/.env` → `%APPDATA%\nk-work-kit\.env` → `~/.config/nk-work-kit/.env` → `.env` beside the script (fallback when running from a clone; gitignored). `check_pending.py` has its own parser (`config_files()`/`load_env()`, copied into `projects.py` and `eleave.py`); `transcribe.py` uses `python-dotenv` in the same order, plus a CWD-upward search. Keep the two aligned when changing lookup. `doc-number` stores no credentials, only a Chromium profile at `~/.local/share/buu-docnum/profile`.
- **Versioning:** a release bumps `version` in `.claude-plugin/plugin.json` (commits are titled `nk-work-kit vX.Y.Z` with a detailed body). Skills carry their own `version` in frontmatter. `marketplace.json` repeats the plugin description, so keep it in sync with `plugin.json`. A breaking change to the install command is a major version.
- **Side effects are deliberate and constrained:**
  - `check_pending.py` is **read-only by construction**. Never open, receive, sign or forward a document: opening one in eDoc marks it read. เอกสารลับ are counted, never opened.
  - eDoc inboxes are discovered at run time. An `EDOC_INBOX`/`EDOC_DIGEST_INBOX` name that is not on the ทางลัด tab is reported as `absent` (0, "likely no new documents"), not an error: an inbox with nothing new can drop off the tab (observed Sept 2026, unconfirmed). The listed names go in the note so a typo still shows, and an ambiguous name is still an error. This is only safe because the tab is read with a stability poll (its links load in stages); keep the poll in both scripts. Name matching ignores whitespace, because Thai titles appear both as "ผศ. ดร. X" and "ผศ.ดร.X". Two counts are reported per inbox: unread/ใหม่ (the actionable one) and the full ค้างรับ list, which the server caps at 500.
  - `edoc_digest.py` writes to eDoc only with `--receive`, and only after a doc's attachments are on disk. It refuses to ลงรับ unless the dialog preselects ไม่ออกเลข/ใช้หมายเลขเดิม (a number book would issue a new เลขรับ), and never signs. It must stay separate from `check_pending.py`, whose read-only promise the `pending-docs` skill relies on. Its docstring has a HARD-WON DETAILS block: ลงรับ only works from `home.aspx` (the dialog lives on the parent page), and attachment links carry per-render tokens. Downloads go to `~/.local/share/nk-work-kit/edoc/<date>/`.
  - `projects.py` writes only `<vault>/<PM_FOLDER>/Dashboard.md`, `<PM_FOLDER>/Kanban.md` (`PM_KANBAN_NAME`; only with `PM_KANBAN=1` or the `kanban` command; Obsidian Kanban plugin format, regenerated from the hubs every time, frontmatter `type: kanban` (and `scan()` skips any note with `kanban-plugin` frontmatter, in case the plugin drops `type` on a drag-save) so `scan()` and the Dataview views skip its `- [ ]` cards — keep that; run `projects_test.py` after changing it), `<PM_FOLDER>/User Manual.md` (from `templates/project-manager-manual.md`, rewritten only when missing or its `plugin_version` differs), new hub notes via `new`, and task lines `scan-inbox` appends to a hub's `## Suggested from inbox` section, all atomically (the vault is synced while it runs); it never edits other notes or any frontmatter, and skips `.obsidian/`, `.trash/`, `Confidential/`. `notify` sends only to `PM_NOTIFY_TO` and only when something is due or a party has been waited on for more than `PM_WAITING_DAYS` working days (Nayot, 23.10.2026) — the user's "no email without approval" rule has a standing exception for exactly this digest. Its config lookup is a copy of `check_pending.py`'s; keep them aligned. Working days skip `THAI_HOLIDAYS` (a static, sourced list for 2026–2027; add each new year's Cabinet list before it starts, or set `PM_HOLIDAYS_FILE`); `waiting_on` stays backward compatible with the single-string form. `gmail-oauth` (the default) uses the bundled Desktop OAuth client `scripts/gmail_oauth_client.json` (Internal consent screen in the BUU Workspace; committed on purpose, since an installed app's secret isn't confidential) unless `PM_GMAIL_CLIENT` or `credentials.json` in the config dir overrides it. The token always lives in the config dir, never beside the bundled client in the version-pinned cache. `scan-inbox` needs `auth-gmail --scan` (adds gmail.readonly + calendar.readonly). It calls `claude -p` as a pure function (`--tools "" --strict-mcp-config --setting-sources ""`, a JSON schema), because email bodies are untrusted: Claude never writes, and the script validates every returned task before appending it. Keep it that way.
  - `eleave.py` writes to e-Leave only with `--confirm`: `request --confirm <preview_id>` submits (the id is a hash of the review-page ใบลา, so what is submitted is what the user saw) and `cancel --confirm` cancels; both e-mail the approvers. The skill must show the preview and get the user's yes for that request first. A `--confirm` run is never retried, and an unclear outcome is reported as `"unclear"` for a `status` check, never resubmitted. A desktop UA is mandatory (the site's WAF blocks headless Chromium's). Its docstring has a HARD-WON DETAILS block (AJAX sub-forms, readonly datepickers set via jQuery, `calculate-leave-days` as the rule oracle, per-type attachment names). Submitting is verified end to end (Sept 2026); the cancel flow was coded from the manual and not yet observed. Its config lookup is a copy of `check_pending.py`'s; keep them aligned.
  - The `transcribe` skill (not `transcribe.py`, which stays vendored) `rclone move`s the audio and its `.md` transcript to `TRANSCRIBE_RCLONE_DEST` after the transcript has been checked and summarised. It checks both names for a clash first, doesn't move the `.md` if the audio move failed, and `none` opts out. For a meeting it also fills in the Obsidian meeting note (`OBSIDIAN_VAULT`): a note the user prepared is filled in place, never duplicated or reworded; otherwise one is created from the vault's meeting template.
  - The plugin's only hook, `hooks/hooks.json` (`SessionStart`, `startup`), runs `projects.py manual --quiet`. Claude Code has no install/update hook, so this is how the manual refreshes after an update. It must stay silent and exit 0 when project tracking isn't set up, and it never creates the projects folder.
  - The `business-card` skill writes Google Contacts only through `gcontacts.py` (`search`/`create`/`update`; auth is gcloud ADC, no token of its own; `create` takes the same JSON as `make_vcf.py` and refuses an email already on a contact by walking the full list, since `searchContacts` lags behind recent creates), because the Contacts MCP is search-only. `update --note` replaces the note, so the skill appends. On Nayot's machine `~/.local/bin/gcontacts` symlinks to the clone's copy, so the clone is the source of truth. If it can't sign in, a new contact becomes a `.vcf` in `~/Downloads/`. The greeting email is only ever a Gmail draft. The skill was ported from a claude.ai skill; it hardcodes Nayot's vCard URL (`https://nayot.github.io/vCard`) on purpose.
  - The `triage` skill is **read-only**: Gmail and WhatsApp through read tools only, eDoc/e-Sign only through `check_pending.py` (never `edoc-digest`, which ลงรับs), run in the **foreground** (a headless run exits before a `run_in_background` job reports). It reads settings via `triage_send.py --show-config`, never the `.env` (passwords). Its only outbound action is `triage_send.py`, which has **no recipient option**: it mails `TRIAGE_TO`/`PM_NOTIFY_TO` (one address) via `projects.py`'s sender and token, refuses an address that isn't the signed-in account when that is knowable (SMTP_USER; Gmail profile if the token has gmail.readonly), and writes `~/.local/state/nk-work-kit/triage/last_run` only after a successful send. `triage_run` (bash, for the `nk-triage` timer) invokes `/nk-work-kit:triage --email` with an allow list of read tools plus `Edit(<state dir>)` (Edit, not Write) and a deny list of every Gmail/WhatsApp send/reply/forward/draft/label/trash/mark-read tool and `edoc_digest`; keep both lists that way. Headless permission checks reject any command containing `${VAR}`, so `triage_run` passes the scripts' absolute path via `--append-system-prompt` and the skill must write it literally in that mode (verified with `claude -p`, Oct 2026). Each source is optional and skipped when absent.
  - **Gmail drafts with links** (the `business-card` greeting, or any skill that drafts email): always pass `htmlBody` with an explicit `<a href="https://…">` for every URL, plus the plain-text `body`. A plain-text-only draft gets its URLs auto-linked by Gmail as expiring `google.com/url?q=…` redirects. `get_draft` read-backs show every link wrapped as a redirect even when the draft is clean, so don't rewrite a draft over that artefact.
  - The `exam-paper` scripts only write into the `--out` folder they are given. The answer-sheet geometry lives only in `exam_omr_layout.py`; the sheet prints an 18-square **layout fingerprint** and `exam_omr_read.py` refuses any sheet whose fingerprint (or ring positions) don't match the spec. Never drop that check: two layouts can put rings one option-pitch apart, and a ring check alone then reads every answer one column off with no flag (found Oct 2026 against the Funda EE sheet). Any change to the layout or the reader's thresholds must be followed by `exam_omr_test.py` (PASS on 40 sheets) before an exam. The reader never guesses: anything not clearly one mark goes to `review.csv`. `exam_cover_form.py` asserts every label of the faculty .docx before writing; `exam_transmittal.py` overlays fixed pixel positions on the scanned "NEW66" form (a new scan needs re-measuring). This repo is public: no exam content, keys, rosters, phone numbers or real rooms go in it, only placeholders in `examples/exam_spec.json`.
  - `pay_sheet.py` writes only inside the DIR it is given (`payments.json`, `qr/`, `receipts/`, the `.tex`/`.pdf`). It never touches a bank: the user scans the QR codes with their own app. QR codes are generated for PromptPay proxies only (mobile, national/tax ID, e-wallet) — the bank-account proxy is undocumented and left out on purpose. The PromptPay payload is asserted against one promptpay-qr reference value at import, so a broken CRC fails before anything is built. `check`/`build` refuse rows that don't add up to `total`, duplicate references, or a paid row whose slip isn't in `receipts/`. The skill ticks a row only from a slip Claude has read; the reply to the requester is always a Gmail draft. No real payee data goes in this public repo — `examples/payments.json` is placeholders.
  - `meet_attendees.py` is **read-only** (GET calls only). `auth` uses the bundled Desktop client (or `credentials.json` in the config dir) with its own scopes and its own token, `meet-token.json` in the config dir, separate from `projects.py`'s Gmail token; `NKW_ACCESS_TOKEN` overrides it for testing (then it sends `x-goog-user-project`). Meet lists conference records only for meetings the user organised, so a code is resolved through `spaces/{code}`'s `activeConference` first (live calls the user joined), then the organiser-only list. A Meet name is matched to a calendar invitee's email only with exactly one candidate: a normalised exact match on the invitee's name, or, for an invitee with no name, its email local part equal to first+last, last+first, first initial+last or all tokens (one-letter first/last names never match; one invitee claimed by two names goes to neither). Never loosen that into fuzzy guessing, and run `meet_attendees_test.py` after changing it.
  - The `reg-grades` skill writes to reg.buu.ac.th only through the user's signed-in Chrome (Claude in Chrome); the user signs in. `reg_grades.py` only prints paste text and JavaScript. The `fill` script saves only when the page's กลุ่ม and `EDITCLASSPOINTID` match its arguments and every box holds the expected value (blank where the CSV is blank — absent, make-up and W students get nothing); `readback` compares the saved columns numerically (reg shows 0.93 as ".93"). New items stay NOT SHOW; the weight total is checked per group (co-teachers' items differ between groups). Its docstring has a HARD-WON DETAILS block. Verified on a 5-group course, Nov 2026. This repo is public: no rosters or marks, only `examples/reg_marks.csv` placeholders.
  - The `tqf3` skill writes to tqf.buu.ac.th only through the user's signed-in Chrome; `tqf3.py` only checks the spec and prints texts and JavaScript. Its page scripts save a section only when every row/CLO/objective in the spec was matched on the page (otherwise they report NOT SAVED); `--no-save` dry-runs. The skill never presses ส่ง มคอ.3. CLOs in the system can't be edited (delete breaks 3.1/4.1 links), and the database drops Greek/math characters — `check` flags them; the docstring has a HARD-WON DETAILS block. Verified on one course, Nov 2026. No real course content in this repo: `examples/tqf3_spec.json` is placeholders.
  - `edu_claim.py` writes only the output PDFs it is given. The two forms are rebuilt from 200-dpi scans of the printed originals: every label, leader, box and rule sits at measured scan coordinates (`edu_claim_layout.py` welfare fund, `edu_claim_gov_layout.py` แบบ 7223), checked by a red/blue overlay on the scan; a field's name is the leader/box it fills, and `fill` refuses an unknown name and runs `check` (child totals, receive = received, Thai baht words) first. After changing a layout, re-overlay it on the scan and check that `blank` output for the other form is unchanged. `pack` never draws a signature. All personal data (profile, certificates, ID card, claim history) lives in `EDU_CLAIM_DIR`, never in this public repo; `examples/edu_claim_*.json` are placeholders.
  - `uniserv_budget.py` only reads the JSON it is given and prints. Its fee rule is the regulation's: a percentage of the **expenditure** (items (1)–(7)), each share rounded up to the ten separately; `selftest` pins the worked case (revenue 195,600 → 170,080 + 11,910 + 13,610) and the ข้อ 19 cap (5,971,120 → 598,556). Run it after any change. `skills/uniserv-project/regulation-2565.md` is the regulation transcribed from the scan (public text); quote it rather than paraphrasing from memory.
  - `docnum.py request` is irreversible and asks for confirmation first. `cancel` works only within 24 hours.
- **`docnum.py` has a "HARD-WON DETAILS" block in its docstring. Do not simplify those behaviours away.** It calls the app's `google.script.run` server functions inside the `script.googleusercontent.com` `/blank` iframe, bypassing the wizard. Chromium must run **headed**, placed offscreen: headless stalls at Google's confirmidentifier. The GPU is disabled. `requester` is an email address, not a name.
- **`transcribe.py` is vendored** from github.com/nayot/autoTranscribe, which remains the source of truth. Upstream is where fixes belong. Local divergences are marked `# LOCAL CHANGE` (shared config lookup, UTF-8 stdout/stderr, ffmpeg/ffprobe resolution + UTF-8 decoding of their output) and must be re-applied after each re-sync.
- **`build_memo.py`** unzips an `.ott` template, rebuilds the ODF `content.xml` body with lxml, and re-zips it (`mimetype` goes first, stored uncompressed). The templates hold only the letterhead, page styles and paragraph styles; the body is intentionally empty. Templates are selected by filename (`แบบหนังสือภายใน.ott` / `แบบหนังสือภายนอก.ott`). The JSON schema is documented in `README.md` and `skills/draft-memo/SKILL.md`. **Layout follows the faculty's Word templates** (แบบหนังสือภายนอก.dotx, แบบหนังสือภายใน-TH Sarabun.dotx; checked line by line against their rendered PDFs, Nov 2026, v2.26.0): label indents and tab stops are measured constants (`LABEL_INDENT`, `NAI_*_INDENT`, TH Sarabun New/PSK advances), runs of spaces become `<text:s>` (ODF would collapse them), the closing/signature block is a keep-with-next chain that takes the last body paragraph (จึงเรียนมา…) to the next page with it, and the หนังสือภายนอก contact box is an as-char frame in its own paragraph right after the signature (so it is always on the last page; a page-anchored box overlapped the signature on a full page). After changing any of this, render a short and a full-page letter and check positions with `pdftotext -bbox-layout`. Dates are Thai Buddhist Era strings (Thai month names, พ.ศ. year; a หนังสือภายนอก date has no "พ.ศ.", e.g. `25 กันยายน 2569`). **Numerals are Arabic by default** (`"numerals": "arabic"`, which also converts any Thai digit in the body to Arabic); Thai numerals (`"numerals": "thai"`) only for documents addressed to สำนักพระราชวัง — BUU rule from 01.11.2569, circular อว 8100/ว 13719 (22.10.2569; administrative committee 10/2569, agenda 5.4.5). The skills must flag a สำนักพระราชวัง addressee to the user.
- `check_pending.py` and `transcribe.py` force UTF-8 on stdout/stderr so Thai text survives Windows code pages (callers pipe the output). Paths go through `pathlib`/`os.path`. Only Linux is tested end to end.
